# 二进制的减法

前面讲过二进制的加法，本章将改造加法器，从而实现二进制的减法。先看一下二进制减法如何计算。

## 十进制减法回顾：借位问题

以 253 − 176 为例：

```
  253
− 176
─────
```

- 个位：3 < 6，需要从十位借 1 → 13 − 6 = 7
- 十位：5 被借为 4，4 < 7，需要从百位借 1 → 14 − 7 = 7
- 百位：2 被借为 1，1 − 1 = 0

结果：**77**

借位处理很麻烦，尤其多位二进制减法，借位会串联传播。我们需要一种**避免借位**的方法。

## 用补数避开借位

### 十进制补数

253 − 176 可以转化为：

```
253 − 176 = 253 + (999 − 176) + 1 − 1000
         = 253 + 823 + 1 − 1000
         = 1077 − 1000
         = 77
```

其中 `999 − 176 = 823` 称为**176 对 9 的补数**（9's complement）。通过补数，我们把减法变成了加法。

> 如果减数大于被减数：
> ```
> 176 − 253 = 176 + (999 − 253) + 1 − 1000
>           = 176 + 746 + 1 − 1000
>           = 923 − 1000
>           = −(999 − 923) = −77
> ```
> 中间出现 `923 − 1000` 仍然需要借位，所以先交换减数和被减数，最后加负号。

### 二进制的一补数（反码）

二进制对 1 求补数更简单——**每位取反**即可（0 变 1，1 变 0），称为**一补数**（one's complement），也叫**反码**。

```
  1111 1111
− 1011 0000   (176)
───────────
  0100 1111   (反码)
```

所以二进制中，**减数的反码 = 1111 1111 − 减数**。

## 二进制减法示例

### 例 1：253 − 176（被减数 ≥ 减数）

```
  1111 1101   (253)
− 1011 0000   (176)
```

转化为加法：

```
  1111 1101                     (被减数)
+ 0100 1111                     (减数的反码)
+ 0000 0001                     (+1)
= 1 0100 1101                   (溢出位)
− 1 0000 0000                   (减去 256)
= 0100 1101                     = 77 ✅
```

竖式：

```
    1111 1101
+   0100 1111  (176 的反码)
+           1
──────────────
  1 0100 1101
− 1 0000 0000  (舍弃溢出位)
──────────────
    0100 1101  = 77
```

> 产生了溢出（第 9 位 1），说明结果为正数，溢出位直接舍弃。

### 例 2：176 − 253（被减数 < 减数）

```
  1011 0000   (176)
− 1111 1101   (253)
```

先求 253 的反码：

```
  1111 1111
− 1111 1101
───────────
  0000 0010   (253 的反码)
```

转化为加法：

```
  1011 0000                     (被减数)
+ 0000 0010                     (减数的反码)
+ 0000 0001                     (+1)
= 1011 0011
− 1 0000 0000                   (减去 256)
= 1011 0010 − 1111 1111
```

这时没有溢出，说明被减数 < 减数，需要交换位置再求补：

```
  1111 1111
− 1011 0010
───────────
  0100 1101  = 77
```

结果前面加负号：**−77**。

### 规律总结

```
结果 = 被减数 + 减数的反码 + 1
```

- **有溢出**（第 9 位进位 1）：被减数 ≥ 减数，差为 0 或正数，舍弃溢出位
- **无溢出**：被减数 < 减数，差为负数，需对结果再取反加负号

> 这种计算方法只能得出数值，无法在二进制中直接表示负数，我们需要一种**能表示负数的二进制编码**。

## 负数的表示：二补数（补码）

8 位二进制可以表示 256 个数字。如果规定最高位为符号位（0 正 1 负），可以这样排列：

```
二进制         十进制
1000 0000     −128
1000 0001     −127
  ...          ...
1111 1111       −1
0000 0000        0
0000 0001        1
  ...          ...
0111 1111      127
```

> 最小负数 `1000 0000` 看起来是最大正数 `0111 1111` 的延续；最大负数 `1111 1111` 比 0 小 1，因为 `1111 1111 + 1 = 1 0000 0000`（8 位截断为 `0000 0000`）。

这种编码称为**二补数**（two's complement），简称**补码**。要将一个负数转为补码：

```
补码 = 1111 1111 − |负数| + 1 = 反码 + 1
```

**求补码 = 取反 + 1**，这正是我们在减法中一直在用的方法。

### 补码的好处

正数和负数可以直接用**加法**计算。

**示例：−127 + 124**

```
  1000 0001   (−127 的补码)
+ 0111 1100   (124)
───────────
  1111 1101   = −3 ✅
```

## 溢出问题

结果超过 8 位能表示的范围（−128 ~ 127）时，结果无效。

**上溢示例：125 + 125**

```
  0111 1101   (125)
+ 0111 1101   (125)
───────────
  1111 1010   = −6 ❌
```

两个正数相加得到了负数——因为结果 250 超过了 127，侵入了符号位。

**下溢示例：−125 + (−125)**

```
  1000 0011   (−125)
+ 1000 0011   (−125)
───────────
1 0000 0110   = 6 ❌
```

两个负数相加得到了正数——因为结果 −250 小于 −128，产生了溢出。

> **判断规则**：如果两个操作数的符号相同，而结果的符号与之不同，则该加法无效（溢出）。
